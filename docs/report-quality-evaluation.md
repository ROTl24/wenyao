# 完整解读的离线评测

这套工具读取本机占簿备份，不调用模型、不上传问题或原文，也不接入正式生成流程。自动检查衡量报告结构和引用是否可定位；推断是否正确仍需人工逐份核对。

## 使用

1. 在占簿中筛选需要审阅的记录，点击“导出当前列表”。备份包含完整报告、锁定排盘、证据快照与复盘。
2. 在项目目录运行以下命令，把路径换成本机文件和输出目录。未指定输出目录时只向终端输出统计。

```powershell
npm.cmd run eval:reports -- --archive "D:/本机评测/占簿备份.json" --output-dir "D:/本机评测/结果"
```

3. 查看生成的“解读评测”文件。工具检查十一节标题、章节顺序、空章节、引用目标、排盘链接和证据快照；停止或失败草稿单独计数，不充当完整报告。
4. 复制“人工评分模板”，打开同一份报告、排盘和古籍依据进行审阅。各项填 `0`、`1` 或 `2`，并在 `reason` 中写出对应章节、论断和理由。没看过的项保留 `null`。
5. 把填写后的评分文件用于汇总：

```powershell
npm.cmd run eval:reports -- --archive "D:/本机评测/占簿备份.json" --reviews "D:/本机评测/人工评分.json" --output-dir "D:/本机评测/结果"
```

报告、排盘或证据改变后，旧评分不能套用。评分指纹与当前材料不一致时工具会要求重新审阅。输出文件使用时间戳，不覆盖已有评分。

## 人工评分

| 维度 | 审阅重点 |
|---|---|
| 盘面事实 | 爻位、六亲、世应、旬空、动变与回头作用方向是否符合锁定排盘 |
| 推断逻辑 | 取用、旺衰、生克与动变是否有依据，章节之间是否矛盾 |
| 证据支撑 | 原文是否支持相邻论断，是否把占例类比写成必然结果 |
| 结论条件 | 信息缺口、成立前提、应期边界与替代解释是否完整 |
| 回答针对性 | 是否回答当前问题，术语是否结合本卦解释 |

`0` 表示明确错误或缺失；`1` 表示部分满足或存在重要遗漏；`2` 表示满足且有可定位依据。每个分数都需理由；仅完整审阅的报告进入各维度均分，未审阅报告不会按零分或满分补齐。

建议固定一组已获准使用的脱敏样本，覆盖八类事项、静卦和动卦、信息充分和不足、证据充足和薄弱等情况。比较两个实现时使用同一问题、排盘与证据，并分别保存两个报告的人工评分。

## 验证边界

自动检查不能证明引用支持论断、领域推断正确或现实预测准确。当前回归使用人工编写的合成文本检验工具本身，未据此声称模型质量提升。真实报告样本与复盘结果应独立审阅；只有在已有授权范围内才进行模型调用。

回归入口：`electron/services/report-quality.test.cjs`。它覆盖完整结构、缺失/伪装/空章节、悬空引用、草稿排除、评分理由和过期评分拒绝。
