# Agent Note: 远程向量建库以完整批次断点和显式恢复为边界

Status: implemented

## Problem

远程向量建库在部分批次成功后可能收到服务商的 HTTP 400、402 或 429。旧流程只把 HTTP 状态归为通用失败，丢弃请求追踪与限额响应头；错误页仍提供“手动继续”，会在服务状态没有变化时再次发送同一失败批次。桌面端只保存成功的完整批次，PWA 则只在全部完成后保存向量，两端的向量文本模板也不一致。

## Decision

桌面端与 PWA 共用服务商失败分类。公开错误只保留 HTTP 状态、允许的请求追踪 ID、Retry-After、ModelScope 限额响应头，以及经过脱敏的结构化错误码；PWA 不保存服务商响应消息。400 中存在明确限额证据时按限流处理，其他 400 与 422 按请求拒绝处理。

每个远程向量批次只有在响应数量和维度有效且本地断点落盘后才增加完成数。失败任务记录零基、右开区间的失败范围，并把向量能力测试状态设为失败。错误状态不允许直接调用继续接口；用户必须先重新执行一次向量最小测试，再从最后一个成功完整批次续建，或明确移除向量和重排能力，以生成模型加本地 BM25 完成配置。暂停状态仍可直接从断点继续。

PWA 在 Worker 内存中保留当前会话断点，并在 IndexedDB 中按批次保存向量块和连续完成元数据；最终索引成功保存后清理批次断点。向量文档统一由共享模板生成。PWA 旧文本格式与桌面格式不同，因此模板版本进入 PWA 缓存指纹；桌面模板保持原语义和原指纹，使已经付费完成的批次断点继续可用。

任何最小测试、远程建库批次和失败恢复都不自动重试。服务商状态未变化时，应用不会替用户重复发起可能计费的请求。

## Alternatives considered

- 对网络错误、限流和服务端错误增加指数退避自动重试：无法确认失败请求是否已经计费，也会在账户限额或固定参数拒绝时重复发送同一批次。
- 仅修改错误文案，继续保留错误页的“手动继续”：无法从运行时阻止重复请求，其他调用入口仍可绕过界面保护。
- PWA 每批覆盖写入整个向量数组：实现简单，但会把逐批持久化放大为随进度增长的重复大对象写入。

## Consequences

用户会看到失败批次范围、安全诊断、检查向量配置和跳过向量两条操作路径。服务恢复后需要一次明确的最小测试，但已成功的完整批次不会重复发送，升级前的桌面完整批次断点也保持可识别。浏览器刷新后可从 IndexedDB 的连续批次断点恢复；IndexedDB 不可用时，当前页面仍可从 Worker 内存断点恢复，并明确提示刷新后可能需要从头构建。
