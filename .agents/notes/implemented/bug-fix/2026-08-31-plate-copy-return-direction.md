# Agent Note: 排盘复制显式区分成卦变化与回头作用

Status: implemented

## Problem

动爻在六爻排盘中按本爻到变爻排列，回头关系则按变爻对同位本爻的作用计算。两者使用同一个无标签箭头时方向相反，外部模型会把正确的两组事实判断为输入矛盾并停止解读。

## Decision

领域事实使用 `changedGanZhi`、`baseGanZhi`、`changedToBaseElementRelation`、`changedToBaseBranchRelation` 和 `returnEffects` 表达回头关系，不使用依赖上下文猜测的 `from`、`to` 字段。历史排盘在读取规范化时重新派生关系事实，因此存量会话继续获得当前契约。

三种复制格式都把本卦与变卦保留为成卦变化，把回头关系明确写成“变爻回头作用于本爻”。自然语言逐项标明变爻、本爻、五行主客、回头作用以及仅覆盖六合与六冲的地支范围。JSON 根对象使用 `schema: wenyao.plate-export` 和 `schemaVersion: 2`，回头关系同时提供稳定的原始枚举和中文标签；`relations.transformationReturnScope` 只约束 `transformationReturns` 的作用方向、五行主语、作用主语与地支关系词表，消费者可以识别不兼容的结构变化。

回头作用文案由共享映射生成，界面与复制格式对生、克、比和、合、冲使用同一术语。没有命中这些已建模作用时只陈述词表范围，不推断不存在化泄、化耗等其他含义；基础关系与主动作用也输出带主客名称的五行和地支标签。未知的五行、地支或作用枚举拒绝导出，不以 `undefined` 或“无关系”静默降级；复制控件记录错误并转为可见提示，不让未处理异常中断结果页，也不要求用户放弃当前排盘。

## Alternatives considered

- 把回头关系箭头改成本爻到变爻会丢失变爻回头作用的主客方向，不能只为视觉一致而改变领域事实。
- 只在解卦要求中增加一句说明仍要求外部模型把无标签箭头与说明正确配对，结构本身继续歧义。
- 只修正文或 Markdown 会让 JSON 和跨运行时复制继续暴露不同契约。

## Consequences

外部模型不再需要通过箭头方向猜测关系类型。JSON 结构发生可检测的不兼容升级；它不是公开兼容 API，但版本字段使脚本和保存的提示模板能够显式拒绝未知版本。地支说明只承诺当前领域模型覆盖的六合与六冲，不把“无”扩大解释为不存在刑、害等未建模关系。

## Verification

`6,7,8,8,9,7` 的风水涣变山泽损回归盘验证本卦初爻戊寅变丁巳、五爻辛巳变丙子，同时将回头关系分别表达为本爻生变爻和变爻回头克本爻。映射测试覆盖五种五行关系、三种六合六冲关系状态与五种回头作用。全量测试、类型检查、Renderer 构建和本地页面三种格式剪贴板读回共同验证跨运行时输出。
