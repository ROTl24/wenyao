# Agent Note: 桌面正式生成按可观测流活动管理等待

Status: implemented

## Problem

Electron 正式解读和追问原先通过 OpenAI Chat 兼容接口读取完整 JSON 响应。移除固定 180 秒总时限后，复杂推理可以继续完成，但桌面界面只能显示不变的转圈提示，无法区分仍在推理、已经开始生成正文和连接真正停滞。

一次本机 DeepSeek 正式解读在检索完成约 4 分 28 秒后才返回，生成用量为 16639 输入 Token、17990 输出 Token，完整报告随后自动保存。该请求不是死锁；静态等待界面和不可观测的 JSON 响应让正常长请求看起来已经卡死。

## Decision

Electron 对仓库内置的 DeepSeek、SiliconFlow 和阿里云生成服务使用 OpenAI Chat SSE：同一请求发送 `stream: true` 与 `stream_options.include_usage: true`，聚合正文并在最终块记录用量。连接最多等待 3 分钟收到首段数据；开始接收后，连续 90 秒没有新数据才判定停滞；持续活跃的流没有固定总时限。

桌面进程向当前请求的渲染进程发送已连接、推理中、正文生成中的阶段事件，以及可展示的最终正文片段；内部推理内容不外传。结果页从检索开始显示阶段和累计等待时间。正文、停止、草稿及应用内后台任务的完整契约见[生成任务与草稿](../feature/2026-09-06-generation-drafts-tasks.md)。

自定义 OpenAI 兼容服务继续使用原有 JSON 响应契约，因为外部兼容接口未必接受 SSE 参数；其界面仍显示检索、连接阶段和累计等待时间。内置服务若在同一流式请求中返回 JSON，Provider 直接解析该响应，不发起第二次请求。所有失败只返回一次结果，禁止透明重试。

正式解读与追问仍不设置应用侧输入或输出 Token 上限。生成模型最小测试、向量建库、查询向量化和重排继续使用各自的有限时限与预算。

## Alternatives considered

- 只增加等待计时：可以缓解静态界面问题，但不能提供服务端仍在产生数据的证据，也不能建立停滞边界。
- 为桌面恢复或提高固定总时限：只能推迟误中止，不能区分长推理和停滞连接。
- 强制所有自定义 OpenAI 兼容服务使用 SSE：会改变既有外部接口契约，且失败后不能安全回退为第二次付费调用。
- 超时后自动重试：服务商可能已经完成部分计费，透明重试会产生重复调用和费用。
- 恢复正式输出 Token 上限或统一关闭思考：会重新引入正文截断，或改变用户选择的模型行为。

## Consequences

内置服务的复杂解读可以超过 180 秒，只要流持续活动就会继续；真正停止产生数据的连接会在 90 秒后结束，并提示用户先核对服务商用量再决定是否手动重试。界面不会展示或保存内部推理；只呈现阶段与最终正文。

关闭应用只会停止本机接收，不能证明服务商已经取消处理。自定义 JSON 服务可由用户停止接收中断连接；若外部服务明确声明 SSE 能力，可再把能力作为持久化协议字段，而不是根据失败自动重试。

## Verification

- Provider 回归先复现 SSE 被当作 JSON 解析失败，修复后验证阶段事件、正文聚合、最终用量和单次请求。
- 模拟超过连接期限但每 80 秒持续活动的流，确认没有固定总时限；模拟未完成中断和连续 90 秒停滞，确认均只失败一次。
- Renderer 回归验证等待时间从 0 秒持续更新到 1 分 5 秒，应用集成回归验证连接、推理和正文生成阶段进入结果页。
- 完整 Renderer 与 Electron 测试、类型构建、PWA 构建、Windows 安装包和发布结构校验覆盖未受影响的探测、检索、网页生成与桌面发布边界。
