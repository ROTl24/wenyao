# Agent Note: 网页 AI 流式解读使用分层超时边界

Status: implemented

## Problem

连接检测使用短提示词，无法代表完整解读的首段响应时间。完整卦象、证据和写作约束会增加服务商开始流式输出前的处理时间；若网页把首段等待与流中断统一限制为 90 秒，会在服务商仍可能处理并计费时提前中止一个可完成的请求。

## Decision

网页生成请求允许最多 3 分钟等待首个响应数据，收到数据后以连续 90 秒无新数据判定流中断。持续产生数据的流没有固定总时长上限。任何超时都只返回一次失败结果，不自动重试计费请求。

收到协议终止标记 `[DONE]` 后，正文完成态立即成立。底层 `ReadableStream` 的取消或释放仅为资源清理，其拒绝不能把已经完成的解读改判为网络失败。

## Alternatives considered

- 所有流式阶段统一使用 90 秒：该边界适合识别已经停滞的流，但不能覆盖复杂解读在服务端开始输出前的处理时间。
- 为活跃流设置固定总时限：该方案会中止仍在正常输出的长解读，不能区分耗时较长与实际停滞。
- 降低完整解读的输出预算：该方案可能缩短部分请求，却会增加十一节报告被截断的风险，不能替代正确的传输阶段边界。

## Consequences

复杂解读在首段延迟超过 90 秒时仍可继续完成，连接检测与正式解读不再共享不合适的等待假设。已经开始且持续产生数据的流不会因累计时长被中止；真正停止产生数据的流仍会在 90 秒后失败，也不会因超时产生透明重试。已经收到 `[DONE]` 的解读不会再因 `reader.cancel()` 拒绝显示“无法连接 AI 服务”。

用户在首段延迟场景下最长会多等待 90 秒，活跃请求的总等待时间取决于服务商输出时长。关闭或刷新页面会停止浏览器继续接收结果，但不能证明服务商已经取消处理。若服务商提供可验证的任务取消接口、稳定的首段延迟指标或不同模型需要独立边界，应重新评估该分层时限。

## Verification

`npm.cmd run test:unit -- src/lib/webAI/provider.test.ts` 验证两分钟首段延迟、超过十分钟的持续流和 `[DONE]` 后清理拒绝都能完成，并保留流中断失败与禁止自动重试的契约。Renderer 构建和 `npm.cmd run verify:web` 验证应用与网页版发布产物。受控 SiliconFlow 线上流程验证最小连接、完整十一节解读和历史自动保存；本地开发页因 Vite 首次依赖优化刷新中断的调用不作为修复后真实验收。`v0.5.6` 发布后，Cloudflare Pages 的 AI Worker 摘要与包含本决策的本地构建一致，关闭旧 Worker 控制的测试标签再打开后加载新主 Bundle。
