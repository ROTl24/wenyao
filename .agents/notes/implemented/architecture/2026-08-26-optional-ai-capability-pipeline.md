# Agent Note: AI 能力采用逐项配置与可选检索链路

Status: implemented

## Problem

最终解读只依赖生成模型。向量召回和专用重排用于提高证据相关性，但不属于生成报告的必要条件。把三项能力绑定成一个完整连接会阻止只有主模型的用户使用 AI，也会把没有向量索引的本地古籍排除在关键词检索之外。

## Decision

配置层以生成、向量和重排三个独立能力保存候选连接、密钥引用和测试结果。生成能力必填；重排能力只能在向量能力存在时启用。渲染层只调用按能力列模型、测试单项能力、完成或取消配置，以及暂停、继续和取消建库的接口。

活动配置与候选草稿分离。单项测试和向量索引准备全部成功后才原子替换活动配置；失败、暂停或取消不会改变旧活动配置。模型目录请求不属于最小测试，任何最小测试和远程建库批次都不自动重试。

运行时始终执行本地 BM25。存在向量能力及匹配索引时增加向量召回和 RRF；存在重排能力时再对融合候选执行重排。已启用的用户古籍无论是否请求向量索引，都会进入本地关键词检索；没有向量能力时，导入和启用古籍不会发起远程建库。

桌面端密钥继续由 DPAPI 或钥匙串保护。PWA 密钥只保存在隔离 Worker 内存中。沿用连接只传递内部能力引用，React 页面不会收到密钥明文。

## Alternatives considered

- 强制生成、向量和重排三项能力全部配置后才允许解读：该方案会让只拥有主模型的用户无法使用本地 BM25 与生成能力，也会把可安全降级的检索链变成硬依赖。
- 只保留生成模型并移除向量与重排配置：该方案无法在用户主动配置检索能力时利用现有向量索引和专用重排改善证据相关性。

## Consequences

设置页按活动能力显示“关键词检索”“关键词 + 向量”或“关键词 + 向量 + 重排”。报告的服务商快照只记录实际启用的能力。旧完整三能力配置保持原运行语义；旧未完成草稿迁移为逐能力测试状态，现有加密密钥和可复用向量索引继续使用。
