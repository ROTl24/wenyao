# Agent Note: 完整报告质量通过离线诊断与人工评分分别评估

Status: implemented

## Problem

检索主题覆盖率只能反映召回，不能说明最终解读是否符合盘面、引用是否支持论断、结论条件是否完整。仅因报告有十一节和引用就报告质量得分，会混淆结构完整与语义正确。

## Decision

`eval:reports` 单独读取用户提供的占簿备份，执行本机 Markdown 结构与引用诊断，并生成带五个维度的人工评分模板。它不接入运行时、不调用模型、不联网、不上传材料，也不作为生成或构建门禁。

自动诊断检查十一节标题、顺序与空章节，核对排盘和证据引用是否有目标，并报告证据快照缺失。代码块与引用块中的伪装标题不能填补缺失章节。未完成草稿单独计数，不进入完整报告样本。

事实一致性、推断逻辑、证据支撑、结论条件与针对性采用人工 0/1/2 分；每个分数需要可定位理由，未审阅为 null。仅完整审阅的报告进入均分，单独报告样本覆盖数量。评分绑定问题、报告、排盘及证据指纹，材料改变时拒绝套用旧评分。

## Alternatives considered

- 用检索 Recall 或引用数量代表解读质量，会漏掉领域事实错误、无关引文和缺失前提。
- 运行时额外调用模型逐句核验会增加费用与等待，并改变用户已确认的单次生成边界。
- 只保留人工均分、不记录理由与材料身份，无法解释评分差异或复验修改后的报告。

## Consequences

开发者可对既有备份离线定位结构问题，再人工审阅语义。自动诊断不是现实预测准确率；当前合成回归证明评测工具行为，不证明模型质量提升。真实基线仍需要获准使用的脱敏报告样本和完整人工评分。增加新报告协议、评分维度或采样规范时应更新模板与说明。

## Verification

`electron/services/report-quality.test.cjs` 覆盖独立编写的合成报告、缺失/空/伪装章节、悬空引用、草稿排除、评分理由与材料变更。CLI 已用合成占簿完成文件读取、诊断和模板输出，人工评分维持未审阅状态。使用方法见 [完整解读离线评测](../../../../docs/report-quality-evaluation.md)。
