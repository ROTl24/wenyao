# Agent Note: 排盘复制由同一结构化事实文档生成

Status: implemented

## Problem

外部模型无法可靠地从排盘截图或界面文本推断完整盘面。可复制内容需要同时保留起卦证据、历法、六爻、关系事实和相关经文，并避免把 AI 解读、追问、连接设置或内部标识带出本机。

## Decision

纯文本、Markdown 和 JSON 均由同一个结构化排盘文档生成。文档只读取当前会话的确定性盘面、问题、分类和起卦记录，并附带要求外部模型核对事实、说明用神依据、区分事实与推断的解卦约束。六爻按上爻至初爻输出，格式选择保存在当前设备。

相关卦辞和爻辞使用独立的六十四卦数据集，不从检索语料中猜测映射。数据绑定维基文库逐卦页面修订号，保留原文字符与标点、来源状态和转录许可。静卦只附本卦卦辞；动卦附本卦与变卦卦辞及本卦动爻爻辞；乾坤六爻皆动时附用九或用六。

历史会话在规范化时升级已有盘面；完整且可重放的六条 6/7/8/9 记录可重建缺失盘面，不完整记录保持缺失，不猜测爻值。剪贴板写入失败时展示完整且自动选中的本地文本，用户可手动复制。

## Alternatives considered

- 复制页面可见文字无法稳定覆盖关系事实、起卦依据与来源元数据，也会让视觉布局成为数据契约。
- 复用应用内部 AI 提示会把检索证据和供应商调用流程耦合到外部复制，且不能提供三种语义一致的格式。
- 从现有检索语料或未校验的第三方六十四卦数据推断经文映射，不能满足逐卦、逐爻完整性与来源可追溯要求。

## Consequences

复制功能在 Web/PWA 与 Electron 的共享渲染层保持一致，不需要增加桌面 IPC 或读取敏感配置。JSON 是稳定的复制表示，但不是承诺永久兼容的公开 API。经典数据增加了随应用分发的体积和来源维护责任；更换文本来源或修订版本时必须重新运行完整性测试并更新许可说明。剪贴板能力仍受浏览器安全上下文和用户授权约束，失败时只保证可手动复制，不绕过平台权限。

## Verification

`npm.cmd test` 验证三种格式的事实边界、隐私排除、爻序、静动卦经文规则、乾坤用九用六、格式记忆、剪贴板成功与失败兜底、历史补建，以及既有前端和 Electron 服务契约。`npm.cmd run build:renderer` 验证共享 Web/PWA 与 Electron 渲染产物可构建；`npm.cmd run build:classics` 验证固定修订可重建为 64 卦、384 爻。

这些检查不证明任一外部模型的解卦质量，也不绕过实际设备的剪贴板授权策略。
