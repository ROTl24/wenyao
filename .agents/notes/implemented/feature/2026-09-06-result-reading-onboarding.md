# Agent Note: 结果阅读复用原文并明确操作状态

Status: implemented

## Problem

报告综合结论位于后部，手机用户需要跨越长篇分析才能找到结果、盘面和古籍。初学者需要问题示例和术语帮助。未执行检索若显示没有命中，会误导用户；弹窗不管理焦点则使键盘操作落到背景页面。

## Decision

结果页从同一 Markdown 语法树定位顶层章节，将第 9、10、11 节完整原文提前展示，保留条件、引用与应期不确定性。界面标明节选来源，提供完整解读和目录，不额外调用模型生成摘要。代码围栏和引用内的标题不作为章节；缺少标准结论章节的历史报告只展示可识别目录及完整原文。

固定导航定位解读、排盘、依据和追问，跳转移入焦点并尊重减少动画偏好。纸页使用 `overflow: clip`，避免 `overflow: hidden` 创建错误的 sticky 滚动祖先。检索区分尚未开始、进行中、已有证据、完成无命中、失败五种状态；缺少快照的历史报告不被推断为已经检索失败。

首页按事项展示可编辑示例，选择事项不改写问题；明确使用示例且已有文本时确认替换。AI 向导突出服务商示例与主模型完成入口，自定义地址和地址用法放入高级设置，实际请求目标及原有域名、费用确认仍可见。排盘提供世应、用神、旬空、动变与六亲的展开解释。

通用弹窗共用焦点管理：打开移入、Tab 在当前层循环、Esc 关闭可关闭的最上层、退出返回触发入口。提交期间保持打开，背景 inert 状态按弹窗栈恢复。

## Alternatives considered

- 再次调用模型生成摘要会增加费用与等待，也可能删除成立条件。
- 只取最后一句结论无法保留综合判断和应期限制。
- 切换事项时自动填问题会丢失用户写入的具体情况。
- 各弹窗独立拦截 Esc 难以统一管理嵌套焦点和背景交互。

## Consequences

阅读更直接，但原文节选仍可能较长，不能保证报告事实与推断正确。章节缺失时不猜测摘要；术语说明只提供入门含义。正文逐段显示、停止接收、后台任务管理和完整解读离线质量评测仍属于后续批次。

- `useModalDialog.test.tsx` 验证焦点循环、恢复、嵌套和提交锁定；既有向导、历史、设置与应用回归继续通过。
