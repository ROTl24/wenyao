# Agent Note: 占簿通过版本化备份和独立复盘保留完整记录

Status: implemented

## Problem

占簿积累了排盘、解读和追问，仅复制盘面不能在清理站点数据或更换设备后恢复使用。回答点赞点踩也不表达事情后来是否发生，不能替代事后记录。

## Decision

历史面板按当前搜索和复盘状态筛选导出 `wenyao-session-archive` v1 JSON。备份采用明确字段，保留原始六爻、起卦依据、排盘、完整 Markdown 报告、追问及各自证据快照、服务商模型标识和复盘；应用设置、密钥及反馈上传授权不属于备份。完整排盘从有效的原始六爻与时间重建，并检查备份卦名和爻值一致性。

导入先校验整份文件，再预览确认，最后通过共享合并入口一次写入。单份限制为 64 MiB、10000 条；坏记录、重复标识或未知版本导致整份失败。冲突检测依据全部本机记录，不受搜索筛选影响，默认保留本机。用户可明确选择另存副本或替换；确认时再次比较预览保存的 `updatedAt`，变化后要求重新预览。副本同步更换报告和追问的反馈目标标识。

Electron 使用临时文件原子替换，并在失败时恢复内存；PWA 通过一次 localStorage 写入更新，容量失败不改变原存储。生成、追问或保存仍在进行时不允许导入，避免旧任务覆盖恢复结果；当前存在待重试保存错误时也不导入。

复盘独立保存待验证、已发生、无法判断三种状态，以及日期、结果备注和个人标签。备注最多 5000 字，标签最多 8 个、每个 20 字；存储边界验证状态与日期。复盘随备份迁移，不进入回答评价上传。异步报告完成时按复盘更新时间合并，保留已保存的实际结果。

停止或失败的生成草稿及对应证据快照随版本 1 备份保留，草稿状态不能伪造为 complete；其运行语义见[生成任务与草稿](2026-09-06-generation-drafts-tasks.md)。

## Alternatives considered

- 逐条普通保存可能在中途失败后只恢复半份，占簿状态难以解释。
- 自动覆盖重复记录不能保留当前设备补充的追问与实际结果。
- 导出应用状态文件会把服务配置、密钥密文和上传授权混入记录迁移。
- 把复盘塞进回答评分会混淆体验与实际事件，改变上传数据含义。

## Consequences

用户能迁移完整可读记录，并主动决定冲突处理。备份是含个人问题和备注的普通 JSON 文件，保管由用户负责；不包含整座用户古籍书库或 AI 配置。PWA 仍受站点存储容量限制，大占簿需要筛选后分批导出；更大数据量需要重新考虑分块存储和备份格式。
